# v0.9.1 · 第二阶段闭环能力与真实诊断

**日期**：2026-11-15（Asia/Shanghai）
**分发状态**：Windows x64 开发预览；GitHub Actions 会在标签验证、完整回归和安装包构建完成后上传 Release 资产。0.x 版本不构成 v1.0 稳定性承诺。

## 这次升级解决什么

v0.9.0 建立了自治运行时和桌面客户端适配器。本版继续补齐运行时的真实诊断、受控交付和安全扫描入口，让客户端能力、工具缺失、远程写入和长时间运行状态都能被明确记录，不再用界面状态代替执行证据。

## 面向用户的变化

- **桌面客户端能力可核验**：ChatGPT Desktop 和 WorkBuddy 使用各自的适配器和 Windows UI Automation 控件树检查，分别报告安装、进程、登录、项目、输入框、发送和结果能力。控件未暴露、客户端忙碌或需要确认时会停在人工接管状态。
- **安全扫描状态可追踪**：CodeQL、Semgrep、Gitleaks、Trivy 支持安装探测、版本记录、Windows 执行、SARIF/JSON 解析、报告保存、历史对比和转任务。工具未安装或依赖审计失败时显示 `BLOCKED`，不会被误报为干净。
- **GitHub 交付更受控**：支持隔离 `nexus/auto/*` 分支、提交推送、草稿 PR、Review、Checks 和 Actions 读取；合并、Release 与通知都需要运行时远程写入开关和明确确认，并分别记录请求与最终结果。
- **后台运行可恢复**：增加持续运行检查模式，覆盖网络中断恢复、服务重启恢复、任务幂等、防重复和资源采样，报告保存在本地测试结果目录。
- **指挥中心显示真实证据**：任务详情和客户端中心展示当前阶段、状态、修改文件、测试、安全扫描、Git Diff、验收、提交和发布状态。

## 验证与已知限制

- 本地完整回归：73 个测试文件、417 个用例通过；TypeScript 类型检查、ESLint 和生产构建通过。
- Windows 主机已真实识别 ChatGPT Desktop 的登录后项目和 Composer 控件；当前会话处于“停止/处理中”，没有可安全触发的发送控件，因此自动发送和真实 AI 改码闭环保持 `PARTIAL`，不会伪造成功。
- WorkBuddy 已独立检测到安装和进程，但当前 UI Automation 树没有暴露项目、输入框、发送或结果控件，相关能力保持 `UNKNOWN`/`unsupported`。
- CodeQL、Semgrep、Gitleaks、Trivy 在本机尚未安装，完整外部扫描报告为 `BLOCKED`；安装脚本提供 Windows `winget` 方案。
- 当前只完成短时持续运行检查；真实 24 小时测试仍标记为 `NOT VERIFIED`。
- 本版安装包的文件名、大小、SHA-256 和签名状态以 GitHub Release 实际资产为准；未配置 Windows 证书时安装包不会宣称已签名。

## 升级与兼容

- 保留 v0.9.0 的既有页面、数据和桌面更新流程。
- 新增的安全扫描和 GitHub 远程写入默认受门禁保护，不会因为打开页面而自动执行远程写操作。
- 如需完整能力边界，请查看 [第二阶段闭环记录](../PHASE2_CLOSEOUT.md) 和 [已知限制](../AUTONOMY_V2_LIMITATIONS.md)。
