# v0.8.5 · 仓库同步校准与定时刷新

2026-11-13 · Windows x64 · 本地开发预览 · 尚未公开发布

## 更新内容

- 修复 GitHub 已删除仓库仍留在本地列表、数量始终不减少的问题。完整同步后，总览、仓库列表、托管选择和项目总览使用同一份当前仓库集合。
- 「同步 GitHub」与顶部刷新会等待后台任务结束，再更新页面并显示结果；连续点击共用任务，显示同步中和最近成功时间。
- 前台约每 60 秒自动同步，窗口隐藏时暂停，恢复后按需同步。控制中心约每 5 秒读取本地任务进度，项目总览保持约 3 秒读取本地快照。
- 仓库列表使用 ETag 条件请求；合并并发请求，按 Retry-After、额度重置时间、服务端轮询提示和连续失败延长间隔。
- 成功取全列表后才将缺失仓库标为不可用，退出当前列表与后续巡检；失败或分页截断时保留未确认记录。保留历史、策略和本地工作区，恢复访问后可重新出现。
- 以 GitHub 仓库身份匹配改名，区分同名重建的仓库；分别记录令牌与 GitHub App 安装的可访问范围。
- 同步状态和本版应用内日志支持现有十种语言，包含此前更新栏布局和归档筛选改进。

## 使用方法

安装后打开「仓库总览」，点击一次「同步 GitHub」，等待完成提示并核对数量。之后保持窗口在前台即可自动刷新。同步只读取 GitHub；不会删除远端仓库或清理已有本地工作区。

## 已知限制

- 仓库数量表示当前连接可访问的仓库，可能包含协作者和组织仓库，不保证总与 GitHub 个人资料页的自有仓库数量相同。
- 移出当前列表不会强制取消已经运行的任务，也不会物理删除历史文件。多连接中仍有连接可访问的仓库继续保留。
- 窗口隐藏、离线、限流或大列表分页时，同步间隔会超过 60 秒。
- 未覆盖当前安装目录，未验收真实跨版本自动安装重启；GitHub 当前公开版仍为 v0.8.2。
