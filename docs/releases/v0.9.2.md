# v0.9.2 · 验证后草稿 PR 交付与桌面体验修复

**日期**：2026-11-16（Asia/Shanghai）  
**分发状态**：已正式发布：[GitHub Release v0.9.2](https://github.com/yuchen0x1/PROJECT-NEXUS/releases/tag/v0.9.2)。Windows x64 仍是 0.x 开发预览，安装包未配置 Authenticode 签名。

## 这次升级解决什么

本版把可靠交付从桌面客户端 UI 自动化中拆出来：客户端只负责执行任务，NEXUS 在独立 Worktree 中收集 Git Diff、独立验收，验收通过后才允许提交分支并创建草稿 PR。这样不会把“任务发送成功”误判为“代码修复成功”。

## 面向用户的变化

- 任务中心新增「创建草稿 PR」动作，仅对 `ACCEPTED`、独立验证 `PASS`、仍保留隔离 Worktree 的任务开放。
- 推送成功后如果创建 PR 遇到网络中断，重试会复用已推送提交，避免空提交和重复分支。
- PR 描述自动记录仓库、基准提交、隔离 Worktree、修改文件和独立验证结果。
- 合并、Release 和通知仍然是独立的人工确认步骤。
- 桌面自动运维按钮统一显示处理中、完成和失败提示；窗口识别失败不会再导致主界面白屏。
- 打包应用按安装目录解析 UI Automation 驱动，真实窗口识别结果会记录到客户端中心。
