# v2.1.0 · PROJECT NEXUS 2.1 — Verified Autonomy Safety and Data Durability

## Summary

This is the reviewed v2.1.0 candidate for PROJECT NEXUS. It remains unreleased
until the real AI, disposable-Windows, signing and public-asset gates in the
2.1.0 reports are satisfied or explicitly accepted by the release owner.

## Highlights

- Added expiring, exact-scope Action Intent grants with one-time consumption,
  route-derived repository scope and auditable grant/use/outcome records.
- Added shared sensitive-path/content detection to provider disclosure,
  operation validation, Diff review and local Agent workspaces.
- Added scheduled and manual SQLite/state backups with integrity checks, WAL
  checkpointing, retention, SHA-256 manifests and staged all-or-nothing restore.
- Added durable Autonomy task checkpoints and corrected verification repair
  scheduling to use the legal `QUEUED` transition.
- Moved the audited UI labels and CSS literals into the ten-locale/theme-token
  system; i18n audit and coverage gates pass.

## Verification

- `npm run check`: typecheck, lint, 81 test files / 539 tests and Vite build pass.
- `npm run i18n:audit`: 0 problems, 0 hardcoded UI strings and 0 CSS findings.
- `npm run i18n:coverage`: all 10 locales at 100%.
- `npm audit --package-lock-only --registry=https://registry.npmjs.org --ignore-scripts`: 0 vulnerabilities.
- See [`PROJECT_NEXUS_2.1.0_TEST_REPORT.md`](../PROJECT_NEXUS_2.1.0_TEST_REPORT.md) and [`PROJECT_NEXUS_2.1.0_SECURITY_REPORT.md`](../PROJECT_NEXUS_2.1.0_SECURITY_REPORT.md) for evidence boundaries.

## Known limitations

- Real AI Provider edit → Diff → test → retry → PR → CI remains **BLOCKED**
  without a disposable repository and temporary credentials.
- Clean install, upgrade, interruption, rollback and data-retention evidence is
  **NOT TESTED** without a disposable Windows VM; Authenticode signing and deep
  Trivy/CodeQL/Semgrep scans are also unavailable.
- No v2.1.0 tag, GitHub Release or Windows installer is created by this
  candidate. The workflow-owned public release must follow
  [`RELEASE_MANAGEMENT.md`](../RELEASE_MANAGEMENT.md) after those gates.
