# v0.8.3 本地产物检查

## 1. 总览

使用 `reverse-engineering-exposure-audit` 的只读 Electron 扫描器检查本地 `release-v0.8.3/win-unpacked`，并对比 0.8.2 扫描基线。扫描 75 个文件、7 个二进制，相对评分 31/D；基线对比没有新增或加重的发现。此评分不是整体安全认证。

原始证据：[扫描与对比](../evidence/v0.8.3-exposure.json)、[归档与 fuse 检查](../evidence/v0.8.3-package-inspection.json)。

## 2. 发现清单

| 范围 | 结论 |
| --- | --- |
| 安装器签名 | `Get-AuthenticodeSignature` 为 `NotSigned`，未配置发布者证书 |
| 归档清单 | 895 个含目录条目，未发现实际 `.map`、环境文件或运行数据/凭据库文件 |
| Electron fuse | Node 环境及调试入口保持既有配置；ASAR 强制加载和内置完整性验证仍未开启 |
| 第三方特征 | PDB 名称、sourceMappingURL 字符串、回环地址等启发式发现与基线一致 |

## 3. 证据与处理

扫描器因大小上限跳过主 EXE；另使用现有 `@electron/fuses` 直接读取了 fuse。RunAsNode、NodeOptions 和 Node CLI inspect 为 enabled；OnlyLoadAppFromAsar 与 EmbeddedAsarIntegrityValidation 为 disabled。没有为了界面修复改变后台通过 RunAsNode 启动服务的既有结构。

ASAR 中的应用版本为 0.8.3，没有 `.env`、`state.json`、`provider-keys.json`、`github-credentials.json` 或 `desktop-settings.json`。更新清单的版本、安装包大小/SHA512、blockmap 与内置官方 GitHub 更新源已由 `node scripts/verify-desktop-update.mjs release-v0.8.3` 核对。

第三方 PDB 名称、托管程序集启发式、源码映射字符串和回环地址继续沿用 [0.8.2 的人工判定](v0.8.2-audit.md)，不将这些信号改写成自有源码或凭据泄漏。未重新执行动态凭据审计。

## 4. 客户端无法解决的问题

应用使用用户自有 GitHub / AI 凭据，没有新增商业授权或订阅判定。本次只处理更新布局与日志，没有把长期凭据放入安装包。Windows DPAPI 仍不能防御同一 Windows 用户权限下的恶意程序；ASAR 也不是保密容器。若未来引入商业授权，应由服务端裁决。

## 5. 后续顺序

继续排除运行数据和源码映射；发布前配置有效签名并验证真实旧客户端安装重启；后台启动方式调整后再评估兼容的 fuse 收紧。本次没有发布远端 Release、安装覆盖当前程序，或将打包程序启动当作跨版本更新验收。
