# Windows 隔离与安装的下一阶段门禁

本文件是待实施/验收方案，不代表能力已实现或已取得系统修改授权。当前严格任务被阻断，更新不能启动安装。

## 原生执行宿主

拟交付独立、可签名的原生 broker，使用明确的窄协议接收工作区 ID、允许命令、超时和输出上限。模型服务凭据留在宿主，不进入执行子进程。broker 不能接受任意项目外路径或开放式 PowerShell 字符串。

每任务 AppContainer / Restricted Token 与 Job Object 配合，创建子进程时暂停，先设置安全属性与 Job 再恢复执行；禁止无保护地先启动再分配。仅给任务临时副本和必要只读工具链授权，默认无网络能力；不授权用户 profile、其他仓库、凭据库、桌面安装目录或当前实例数据目录。所有句柄按明确列表继承，拒绝普通环境回退。

需要单独批准的具体动作：创建/删除 NEXUS 专用 AppContainer profile，修改对应临时工作区和必要工具链的 SID ACL，可能需要网络策略测试；改前导出 ACL 与 profile 标识，失败只回收本次创建的对象。不会笼统授予整盘权限或创建管理员账户。

验收必须真实尝试读取未授权目录/凭据、写入原项目/安装目录、连接网络、衍生进程逃逸、超时和内存/进程上限，并确认拒绝记录。缺少任一核心边界不能标为严格隔离可用。

## 原生安装事务

输入必须来自当前受认证更新服务的 Verified 候选，安装前重新验证完整 SHA-256、大小、Authenticode 链及明确受信发布者。当前候选未签名，因此该门禁仍关闭。证书由用户选择既有证书或正式签名服务，不自动购买、生成并信任根证书。

拟采用外部 updater helper，在安装目录之外持久化事务：Prepared → BackedUp → InstallAuthorized → Installing → HealthChecking → Confirmed，失败进入 RollbackRequired / RolledBack / DataRecoveryRequired。安装只在原生确认、无活跃写入任务且应用安全退出后执行。版本发现、下载、候选批准不等于安装授权。

备份范围需在实际安装路径确认后固定：上一可运行程序的拥有文件清单及摘要、应用负责的版本化 JSON/配置清单。备份不得包含可跟随到任意目录的链接；不得用“整目录递归删除”实现回滚。用户数据原件保留，数据迁移先在副本检查，当前数据若发生独立修改不得被旧备份自动覆盖。

安装成功还要启动新版本，核对版本、API ready、JSON schema、配置读取和必要的无远程写入健康检查。失败只回滚本事务拥有且内容仍符合事务预期的程序文件；遇到用户并发修改、数据格式不兼容或不确定状态停止并提供备份位置。保留上一可运行版本直到健康确认。

需要单独批准的动作：配置实际发布者/签名凭据、退出正在使用的应用、在用户确认的安装目录运行经过验证的安装器、故障注入和跨版本重启验证。真实 Windows 重启需另行明确同意及恢复点，不能从普通进程重启授权推导。

远程推送、打 tag、创建/发布 Release 仍是独立动作。本轮本地候选、报告和测试不授权这些操作。
