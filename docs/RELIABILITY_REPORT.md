# 持久化与恢复报告

日期：2026-11-13。总体 PARTIAL：安全会话边界续跑和真实 API 进程崩溃恢复通过；任意步骤自动续跑、真实 Windows 重启与断电验收未完成。

## 已完成的可靠性边界

新增版本化 JSON、同进程串行更新、跨进程租约和 revision 比较更新。写入复用 fsync、备份与原子替换，Windows 共享冲突仅对 EPERM/EACCES/EBUSY 有限重试。损坏记录阻断后续执行，不能默默当成新任务覆盖。

Runtime 在工具执行前持久化操作意图，执行后保存回执摘要；模型调用前保存完整的有界对话、工作区实际文件指纹、提供方/模型/目标身份、预算及累计时限。已完成的独立审查也计入 token、费用及请求次数。没有用量的响应记录为未知用量，缺少价格时不显示免费。

可恢复的边界是 `model_pending`：对应已完成的工具观察已经进入对话，而没有未核实的写入。重启后显式确认，重新验证身份、摘要和工作区字节，复用原任务与原工作区，跳过重新规划。可能已消耗但未收到回执的模型请求保留不确定预算，不能通过重启重置总预算或时限。

`operation_pending`、尚未保存完整后续对话的工具回执、审批/测试/审查中的不确定状态不自动重放。已完成子任务若先保存了成功回执、父角色回执随后丢失，可核对文件指纹后补齐父记录，再继续剩余角色。未知写入无法验证时保持阻断。

窗口关闭沿用托盘后台行为；退出程序改为经父子 IPC 请求服务安全停止，先中止请求与工具、保存状态，超出退出期限才终止，重启后检查遗留任务。关闭窗口、退出应用、Node 崩溃和 Windows 重启是不同验收项。

## 真实证据

真实启动 API 子进程，等待开发角色完成一次文件写入并进入下一次模型调用，强制结束该进程，然后复用同一数据目录启动新进程。恢复后使用相同子任务 ID，规划仅调用一次，保留前次写入的工具观察，完成真实测试和审查；原项目仍保持初始内容。见 `ultimate-real-process-recovery.log` 以及最终完整回归中的相同测试。

另有对话摘要篡改、工作区内容变化、缺失工具回执、磁盘写入失败、并发 revision、超时、暂停、取消、基线提交变化、链接路径和备份失败测试。原生窗口完成“运行 → 暂停 → 恢复中心确认续跑 → 完成”与真实记忆导出。

## 远程副作用

保留既有 durable-effects 的唯一操作键、Prepared/Confirmed/Uncertain 状态，分支/提交/PR/合并/Release/资产/评论/Issue 状态需要查询真实远端回执，不能盲重放。fixture 测试可以验证请求与回执协议，但本轮没有修改真实远端仓库，不能标记本版本线上幂等交付通过。部分查询有分页上限，未查询到不代表操作一定未发生。

## 未完成与限制

真实 Windows 重启、真实断电、真实网络断开、真实 GitHub 限流后的远端交付续跑没有本轮证据。安全续跑不是任意工具执行到一半时的透明恢复；损坏的新 evolution 记录也不自动恢复备份覆盖原件。候选应用保存事务和备份，但断电中的部分应用仍要求用户核对。24 小时持续运行独立记录在性能与验收报告中，不能由以上短测试替代。

退出处理补充了 IPC 和父进程存活监测。原生崩溃验收首次误杀了 Playwright 启动器，后经进程树确认其 PID 与实际 Electron main PID 不同，已改为终止真实主进程；不能将启动器退出当作应用崩溃。强杀可能留下属于已退出进程的租约，验收要求同 profile 重启核实并回收租约、保留已完成工作流且不重跑模型，并不虚构“任何崩溃都能优雅清理”。

每个角色在调用处理器前持久化预算预留。硬崩溃恢复会把未结算预留转为不确定用量，防止没有回执的请求通过重启获得预算重置。缺失、负数和空字符串的提供方用量不会被记录成免费请求。

同步盘长稳在两个角色获取同一证据锁时发现 Windows EPERM。现已增加有限重试，始终保留原子租约，持续拒绝时失败关闭。新增测试验证互斥、二进制摘要不变，以及取消后不返回未经保护的证据。
