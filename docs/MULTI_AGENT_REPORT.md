# 多 Agent 实施报告

日期：2026-11-13。开发版本 0.8.0，分支 `codex/ultimate-evolution`，未发布。总体 PARTIAL：本地真实执行链通过；真实外部模型及严格隔离环境尚未验收。

## 实施结果

保留原有 Provider、34 工具和多轮 Runtime。新增固定六角色适配器与依赖图：Planner → Researcher → Developer → Tester / Security → Reviewer。每个模型角色获得独立 system prompt 和依赖结果，角色没有自行创建子 Agent 的工具。图检查拒绝循环、未知依赖和重复 ID；工作流具有总 token、角色超时、总时限、并发和重试上限。

Developer 创建独立 Worktree 或有界副本，保存基线提交和实际文件指纹。Tester 在第二个副本中设计并新增 `node:test` 测试，保护既有测试和生产文件，同时执行原有测试/构建。无法编写此类测试时明确记录空测试列表和覆盖限制，不伪造测试。Security 扫描开发候选；Reviewer 使用新的上下文阅读 diff、真实检查结果和独立测试摘要，校验测试文件指纹。

角色结果、模型选择、消息、用量、工具意图、审批和检查点写入持久记录。候选完成必须同时满足真实测试成功、安全结论和独立审查批准。完成不自动应用、推送、发布或安装。测试工作区不能作为开发候选直接应用。

## 现有限制

Researcher 在有来源报告时分析固定源码证据，普通任务则明确标为本地项目上下文；尚不是可任意联网浏览的研究 Agent。独立新增测试当前限定 Node 内置测试；其他语言仍依赖既有工具链。审查提出修改意见会记录并阻断候选，没有无限自动往返修复。

普通执行仍具当前 Windows 用户权限。严格模式缺少可信原生宿主时直接阻断。默认六角色适配器不是任意规模的分布式 Agent 平台；资源调度和真实服务验证边界见相应报告。
