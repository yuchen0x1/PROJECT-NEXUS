## 3. i18n quality gates

- Key parity test treats en-US as the baseline; ru-RU must additionally provide `_few`/`_many` for every plural key (CLDR).
- Placeholder parity guarantees no interpolation drift across languages.
- Missing-key scan covers literal and dynamic `t()` usage across `src/` (including `useTranslation` import check).
- Dev-mode `saveMissing` logs unresolved keys to the console during development.
- Translation coverage report generated by `npm run i18n:coverage` → `docs/PHASE5_TRANSLATION_COVERAGE.md`.

## Known limitations

- The tray menu language is applied at launch from the saved preference; it does not follow a live language switch (Windows tray menus are rebuilt on next start).
- Agent event lines of unknown types and all provider/service-generated messages render as raw text by design (see i18n architecture §6).
- Screenshots other than those listed in the delivery report were not re-captured for every language; the language-agnostic E2E asserts structural correctness for the covered switch paths instead.
