# 第一次开启自动维护

首次启动应用会自动打开教学，说明当前位置、要填什么和完成后去哪儿。之后也可从工作台或顶部的「一键教学」重新进入。填好后点「下一步」，会先保存并检查，通过后才继续；出错时留在当前步骤重试。

尚未准备好账号或密钥时，可点击「稍后继续」或关闭教学；下次启动仍会提醒。配置完成后点击「带我看运行位置」，跟随四个功能页面了解任务和结果，最后点击「完成教学，查看托管」。全部教学完成后，后续启动不再自动弹出。仅打开或关闭教学不会自动授予脚本执行或远程写入权限。

1. **连接 GitHub**：点击「获取 GitHub 访问令牌」，到官方页面创建后粘贴。已有连接可直接下一步，不必重新输入。
2. **配置 AI**：填写 API 类型、Base URL 和 API Key，点击默认模型旁的「获取模型」，在下拉列表中选择模型，再保存并测试。也可直接输入模型名。已保存的连接可以复用密钥；修改地址或类型后需重新填写密钥。接口不支持模型列表时继续手动输入即可。
3. **选择 GitHub 仓库**：必要时先同步 GitHub，然后勾选一个或多个仓库。点击「全选」一次选择全部已同步仓库，「全不选」清空选择；可以搜索，已选数量会持续显示。后续策略、检查和托管将应用于全部所选仓库。
4. **检测本机工具**：自动修复需要 Git，测试和构建还需要项目对应的运行环境。缺少工具会提示，不会自动安装。
5. **选择策略**：要自动处理符合条件的问题，选择「全自主模式」，明确勾选可信仓库脚本授权，再选择检查间隔。保存变更会暂时关闭该仓库托管，最后一步重新确认开启；原策略未变时保留现有状态。
6. **检查仓库**：教学读取真实仓库并测试 AI 与工具。基础检查成功不代表所有 CI、签名和发布条件已通过，交付时还会继续验证。
7. **确认并开启**：明确勾选远程写入授权。如果全局巡检处于暂停状态，先点击「恢复自动巡检」，然后开启托管。

批量步骤会逐仓库显示进度、成功和失败。部分失败时修正原因并点击「重试未完成项」，成功项不会重复处理。可点击「停止批量操作」停止后续请求，当前请求完成后保留结果。检查全部通过后再开启托管；开启时某个仓库失败不影响其他仓库的成功结果。

开启全部成功后，会显示仓库清单和检查间隔。没有符合条件的 Issue 时，会继续监控而不创建修复任务。需要马上检查，可以点击「立即检查 Issue」；这会同步真实问题，并按已确认的策略判断是否排队。

电脑需保持开机，窗口可关闭到托盘；完全退出程序会停止本机任务。

## 到哪里看结果

左侧「工作区 → 项目总览」打开运行关系图。账号位于中心，仓库分布四周，内圈连接 AI、巡检、规划、执行、测试、交付与研究。滚轮缩放、拖动平移，点击「显示全图」恢复视野；也可搜索、筛选或从「定位仓库」选择目标。

点击仓库或 AI 节点，在右侧查看任务、模型连接和近期真实输出，点击任务进入对应功能页。底部「运行输出」可展开查看事件。页面约每 3 秒刷新，显示的是任务级活动，不是逐字生成的模型文本流；没有运行任务时不会显示流动连线。等待审批、完成、断线和后台隐藏时停止相应动画。打开关系图只查看记录，不会启动任务。

完成设置后点击「带我看运行位置」，教学会依次跳转并标出对应区域：

- **管理 → 托管**：仓库是否启用、策略、间隔、交付权限，以及暂停、恢复和关闭入口。
- **管理 → 任务中心**：执行与交付分别显示结果。阻塞时展开原因和远端回执；审批请求会在通知与 AI 智能体中提示。
- **管理 → Issue**：查看问题和分类依据。只有符合策略、置信度和风险要求的问题才会进入自动修复流程。
- **管理 → 研究**：查看按计划产生的源码研究，或手动运行研究，审阅升级建议和许可证。

管理功能全部平铺在主侧栏，直接点击即可；无需先打开「远程控制台」。工作台、本地项目和开发环境固定在上方，较长的管理列表可以滚动。

## 当前自动化的范围

当前可以自动巡检、分类，并对符合条件的 Issue 执行修复、测试、审查和授权交付。CI 失败、权限不足或验证不通过会停止后续交付。研究生成的升级提案仍需审阅，批准提案不会自动实施任意升级；非 Node 项目的通用自动发布尚未完成。

## 归档仓库的选择（v0.8.4 本地预览）

在「选择仓库」步骤中，列表默认只显示未归档的仓库，每行右侧标记「正常更新」。勾选「显示已归档」可查看归档项目，它们标记为「已归档」且不可选择，不计入全选和已选数量。

归档状态来自 GitHub；归档或解除归档后，点击「同步 GitHub」刷新。已选项目归档后会取消选择；解除归档并同步后可以重新选择。全部归档时列表提示没有可托管仓库。正常更新标记只表示仓库未归档，不代表任务当前正在运行。

## 仓库同步与刷新（v0.8.5 本地预览）

连接 GitHub 后，前台约每 60 秒同步一次仓库列表。窗口隐藏时暂停；回到窗口后，达到刷新时间便会同步。GitHub 要求等待或发生网络错误时会延长重试间隔。

需要马上更新时，点击「同步 GitHub」或顶部刷新按钮。界面会显示「正在同步 GitHub…」，等待任务结束后更新仓库列表、数量和最近同步时间。连续点击会共用正在执行的任务。

GitHub 上删除或当前连接已无法访问的仓库，在完整同步成功后退出当前列表、托管选择和后续巡检。历史任务、策略与本地工作区仍保留；不会因一次网络失败或分页不完整清空仓库。重新恢复访问并同步后，原记录可重新出现。

控制中心的任务进度约每 5 秒读取本地数据，项目总览沿用约 3 秒的本地刷新；这些刷新不会再次拉取 GitHub 仓库列表。旧版客户端需安装新版才能获得此行为。
