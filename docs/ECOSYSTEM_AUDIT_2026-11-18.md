# 生态升级审计进度（2026-11-18）

这是未完成的审计记录，不是多平台交付或发布验收报告。

- 基线：`main`，`0ce8c62`，版本 0.9.3；远程为 `yuchen0x1/PROJECT-NEXUS`，MIT 许可证。最新 Release 为 Windows x64 开发预览，包含安装器、blockmap、更新清单与 SHA-256 清单。
- 当前产品以 Windows Electron 工作站为主，Node/Express 服务和 React 界面同时提供本地 Web 控制台。服务未实现多用户认证，不应暴露到不可信网络。其余平台需要独立评估和真实验证，不因共享代码或容器配置存在而视为正式支持。
- 仓库已有 Windows 发布工作流；截至检查时主分支无保护，日常 PR 缺少 CI。本次新增的 CI 与 Dependabot 配置尚未在 GitHub 上运行，不能视为已验证。分支保护应在 CI 首次成功后再根据实际检查名称设置。
- Windows 安装包与更新资产已存在，但现有发行版本未配置 Authenticode 签名。摘要文件不能证明发布者身份；旧客户端发现、校验、安装并成功启动新版本的完整过程尚未验证。
- 官方 npm registry 的生产依赖审计返回零已知漏洞；这只是该时间点和该依赖范围的结果。默认镜像不支持 npm audit 接口。
- 本轮确认并修复默认回环 Web 服务拒绝自身来源导致页面资源加载失败的问题。测试中还发现旧 API 夹具未隔离全部数据目录，已调整夹具。测试期间项目 `data/` 内出现 `autonomy.db`、SQLite WAL/SHM 和 `local-agent-tasks.json`；这些文件保留，未清理或恢复。
- 初始 `npm run check` 的类型检查和 lint 通过，未限制并发的测试出现大量超时并被中断。两 worker 严格超时的运行也失败；放宽超时的定向 API 测试在隔离修复前曾通过 5 项，隔离修复后单独运行有 3 项通过、2 项失败（任务轮询超时和服务未在等待窗口内就绪），仍需复核原因。构建和隔离 Web 实例的浏览器渲染通过。
- 现有 `COMPETITOR_ANALYSIS.md` 记录 16 个项目，`UPGRADE_ROADMAP.md` 记录 36 项历史候选；均不等于本轮要求的 30 项逐个最新研究和平台可行性评估。
